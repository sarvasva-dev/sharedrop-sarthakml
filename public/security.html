1. The WebRTC DTLS Cryptographic Guarantee

ShareDrop utilizes the W3C WebRTC DataChannel standard (RTCDataChannel). Unlike traditional cloud services where files upload to a server and are re-downloaded by the recipient, WebRTC creates a direct, authenticated, and encrypted channel between the two devices:

  • DTLS Key Exchange: Browsers negotiate session keys directly using ECDHE (Elliptic Curve Diffie-Hellman Ephemeral) key exchange during the ICE connection phase.
  • Payload Encryption: All file slices, directory trees, and clipboard payloads are encrypted using AES-GCM (256-bit) at the network interface before packet transmission.
  • No Server Man-In-The-Middle: The signaling server only relays the initial SDP handshake containing public cryptographic fingerprints. The server never possesses the private keys required to decrypt DataChannel packets.

2. Anti-IDOR Room Isolation Protocol

In insecure signaling implementations, an attacker knowing another peer's UUID can inject arbitrary signals or spoof file transfer offers (Insecure Direct Object Reference). ShareDrop eliminates this vector entirely:

// Anti-IDOR Membership Verification Invariant (RoomManager.js)
if (!roomManager.arePeersConnected(senderId, targetId)) {
  return sendJson(ws, {
    type: 'error',
    code: 'UNAUTHORIZED_TARGET',
    message: 'Target peer is not in your discovery room or paired group'
  });
}

Every incoming signaling message (signal, file-offer, text-beam, ws-chunk) must pass mutual room membership verification before forwarding. Even if an adversary guesses a peer ID, cross-room routing is strictly prohibited.

3. 6-Digit Pair Code Cryptography

To connect devices across separate networks (such as 5G mobile and home Wi-Fi):

  • Ephemeral 6-Digit Code: Cryptographically random 6-digit numeric string generated via crypto.randomInt(100000, 999999), valid for only 5 minutes.
  • Rate Limiting: Pair code verification is protected by per-socket and per-IP rate limits (maximum 5 attempts per minute), rendering brute-force attacks statistically impossible within the 5-minute TTL.
  • Persistent Pair Secret: Upon successful code exchange, the server mints a 32-byte cryptographically secure random token (pairSecret) shared exclusively between the two devices. In all future visits, devices subscribe to paired:sha256(pairSecret), enabling permanent mutual recognition across any network without credentials.

4. Memory-Bounded Flow Control

Streaming multi-gigabyte files can quickly exhaust client memory or crash browser tabs if unthrottled. ShareDrop enforces strict streaming backpressure:

// Client Backpressure Control (webrtc.js)
const CHUNK_SIZE = 65536; // 64 KB
channel.bufferedAmountLowThreshold = 524288; // 512 KB

while (offset < file.size) {
  if (channel.bufferedAmount > 2 * 1024 * 1024) {
    await waitForBufferedAmountLow();
  }
  channel.send(slice);
  offset += CHUNK_SIZE;
}

This guarantees smooth memory usage, maximum link throughput, and zero tab crashes across low-memory mobile devices.
